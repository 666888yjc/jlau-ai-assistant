# 吉小农 · 运营上线指南（Coze + 公众号/抖音 + Token 安全）

> 目的：本指南把"已通过 QA 的工程薄壳"接上"真实吉农知识大脑"，让吉小农从 mock 演示变成能答真问题的新生助手。
> 适用对象：负责上线的运营同学（在校学生即可，零代码为主）。
> 配套文件：`docs/knowledge-base/`（知识库素材）、`docs/SPEC.md`（验收标准）、`README.md`（工程启动/部署）。

---

## 0. 两条上线路线（先选）

| 路线 | 做法 | 优点 | 取舍 |
|------|------|------|------|
| **A. Coze 直发渠道（最快，推荐先用）** | Coze 建 bot + 导知识库，直接在 Coze「发布」绑定微信公众号/抖音号。新生在微信/抖音原生对话里问。 | 零部署、零付费、当天可跑通真问答；最适合 8–9 月报到前验证。 | 走微信/抖音原生界面，不使用我们定制的 H5 UI（微信绿/薄荷绿气泡、猜你想问卡片、反馈按钮）。 |
| **B. 薄壳 H5 + Coze 大脑（完整产品）** | Coze 只作大脑，自建 H5 经 CloudBase 云函数代理调用（工程已做完），公众号菜单/抖音主页挂 H5 链接。 | 保留定制 UI + 反馈 + 兜底转人工 + 来源标注。 | 需部署 CloudBase（连腾讯云账号），token 注入云端环境变量。 |

**建议**：先用 A 在 8 月跑通真问答、收集新生高频问题；等想对外正式推、要品牌 UI 时再走 B。两条路共享同一份 Coze 知识库，不重复建设。

## 1. Coze 智能体搭建（A、B 路线共用）

1. 打开 Coze 国内版 https://www.coze.cn ，用手机号注册/登录。
2. 左侧「创建智能体」→ 名称填「吉小农」，简介「吉林农业大学新生报到答疑助手」。
3. **人设与回复逻辑**（粘贴以下提示词，按实际微调）：

```
你是「吉小农」，吉林农业大学面向新生的校园 AI 助手，当前只负责「新生报到」单场景。
# 身份与边界
- 你只基于「吉林农业大学新生报到知识库」回答，不编造、不猜测未收录的信息。
- 知识库未覆盖或你不确定时，明确说"这个我不太确定"，并引导联系招生办 0431-84532980 或学院学工办，不要给模糊答案。
# 回答风格
- 用简体中文，口语亲切但不过度卖萌；分点、列清单，关键信息（时间/地点/金额/电话）务必准确。
- 涉及日期以录取通知书和学校最新通知为准，若知识库与最新通知冲突，提示用户"以通知书为准"。
# 合规
- 不收集身份证号、银行卡号、家庭住址等隐私；不提供医疗/心理诊断，仅共情引导并建议联系学校心理咨询中心。
- 每条回答结尾标注"AI 生成内容，仅供参考"。
```

4. **添加知识库**：
   - 进入「知识」→「新建知识库」→ 选「文档」类型，命名「吉农新生报到」。
   - 把 `docs/knowledge-base/` 下的 `01-报到流程.md` … `11-联系方式求助.md` 共 11 个文件逐一上传（或打包上传）。
   - 等待索引完成；可在知识库内预览分段是否准确。
5. **模型与检索**：
   - 模型选平台默认大模型（如豆包等），中文对话质量足够。
   - 在智能体编排里开启「知识库检索」，把刚建的知识库关联上；可开启「引用来源」以便回答标注出处。
6. **获取 bot_id**：智能体「发布」前，在「开发」页 URL 或「API 调用」处复制 `bot_id`（形如一串数字），后续路线 B 要用。

## 2. 路线 A：直接发布到公众号 / 抖音（零部署）

### 2.1 微信公众号
1. Coze 智能体页 → 「发布」→ 渠道选「微信公众号」。
2. 用公众号管理员微信扫码授权（订阅号/服务号均可；个人主体用订阅号）。
3. 授权后，用户在公众号对话框发消息即可与「吉小农」对话。
4. 想用定制 UI 时可不选此渠道，改为路线 B，把公众号菜单指向 H5 链接。

### 2.2 抖音
1. Coze「发布」→ 渠道选「抖音」/「抖音私信」。
2. 用抖音号扫码授权，智能体即可在抖音私信中应答。
3. 或在抖音主页「添加链接」挂 H5 地址（路线 B 部署后）。

> 注意：微信对「AI 问答」类目审核较严，若公众号渠道受限，优先用抖音私信或路线 B 的 H5 链接，仍符合 SPEC「个人主体走公众号/抖音」的合规判断。

## 3. 路线 B：薄壳 H5 + CloudBase（完整产品，需部署）

> 工程已就绪（`web/` 前端、`server/` 后端、`cloud-functions/api/`）。部署详见 `README.md` §8 与 `docs/DEPLOY.md`。此处只列上线动作顺序。

1. 连接腾讯云账号（当前 CloudBase 连接器未连接，需在 WorkBuddy 连接或到 CloudBase 控制台操作）。
2. 编译后端：`cd server && npm run build` → `server/dist`。
3. 打包 `server/dist` + `node_modules`（含 express）+ `cloud-functions/api/index.js` 为 HTTP 云函数；前端 `web/dist` 托管到静态网站（同源）。
4. 配置云函数环境变量（见 §4）。
5. 如需真·逐字流式，改用「Express 直接挂 HTTP 函数」透传入口（见 DEPLOY.md），而非缓冲适配器。
6. 公众号菜单 / 抖音主页指向你的 H5 域名（需绑 HTTPS）。

## 4. COZE_TOKEN 安全注入（红线，务必遵守）

薄壳后端**是唯一**持有 `COZE_API_TOKEN` 的地方，前端永远不持有、不出现该 token。

| 项 | 做法 | 禁止 |
|----|------|------|
| 本地联调 | `export COZE_API_TOKEN="pat_xxx"`、`export COZE_BOT_ID="123"`、`export COZE_MOCK=false` 后 `npm start`（参考 `.env.example`） | 禁止把 token 写进代码或提交到仓库 |
| 云端（路线 B） | 在 CloudBase 云函数「环境变量」里添加 `COZE_API_TOKEN` / `COZE_BOT_ID` / `COZE_API_BASE=https://api.coze.cn` / `STORE_KIND=cloudbase` | 禁止写入前端代码、前端环境变量、或前端可访问的配置接口 |
| 防泄露 | token 仅运营负责人掌握；轮换时只改云端环境变量，不动代码；`.gitignore` 已排除 `.env` | 禁止在聊天/截图/公开文档暴露完整 token |
| Mock 兜底 | 未配置 token 时后端自动启用内置 mock 流（AC-03 兜底可演示），不影响前端联调 | — |

环境变量清单（与 `.env.example` 一致）：

```
COZE_API_TOKEN=        # 必填（生产）；空则强制 mock
COZE_BOT_ID=           # 必填（生产），§1 第 6 步获取
COZE_API_BASE=https://api.coze.cn
COZE_USER_ID=jlau-shell
COZE_MOCK=false        # 生产置 false
STORE_KIND=cloudbase   # 生产用云存储
PORT=3100              # 本地联调避前端冲突
```
