### 0.1 原始需求复述

用户希望把开源项目 MaiBot（LLM「数字生命」对话机器人）中**与机器人无关的通用产品能力**迁移到吉小农，共 4 项：

1. **学生档案 / 个性化记忆** —— 记住用户是谁、学什么专业、关键偏好，并据此个性化。
2. **可插拔模块系统** —— 像装插件一样扩展功能，模块独立、可开关、有中心入口。
3. **表情贴纸回复** —— 用吉祥物表情/贴纸替代纯文字，增加亲和力。
4. **数据导入与记忆隐私** —— 允许导入个人笔记，并让用户清晰掌控自己的数据。

## 1. 产品目标

让吉小农从「一问一答的通用问答页」变成「**认识我、能被我改造、且我完全掌控**的校园助手」：新生首次填完一张 30 秒的档案卡后，每次打开都能收到带自己昵称与专业的问候；模块中心让「校历作息」「周边美食」这类高频刚需从对话里沉淀成可一键直达、可自由开关的常驻入口；同时用一个隐私中心把所有本地数据摊开给用户看、让他随时导出或一键清空——在**不引入账号体系、不改动后端一行代码**的前提下，把「亲和力」和「掌控感」同时补齐。

## 2. 用户故事

### 能力一：学生档案 / 个性化记忆

| # | 用户故事 |
|---|---|
| US-01 | 作为一名**刚入学的新生**，我想填写自己的昵称、专业和年级，以便助手叫得出我的名字、不再用千篇一律的「同学你好」跟我说话。 |
| US-02 | 作为一名**长期使用的用户**，我想把自己说过的关键偏好（如「我在东区宿舍」「我不吃辣」）保存下来，以便助手下次打招呼时能顺带关心到我在意的事。 |

### 能力二：可插拔模块系统

| # | 用户故事 |
|---|---|
| US-03 | 作为一名**新生**，我想在一个统一的「模块中心」里看到助手提供的所有附加功能，以便我一眼知道它到底能干什么，而不用靠猜着提问去试探。 |
| US-04 | 作为一名**已经熟悉校园的老用户**，我想关掉自己用不到的模块，以便首页保持清爽、只留下我真正需要的入口。 |

### 能力三：表情贴纸回复

| # | 用户故事 |
|---|---|
| US-05 | 作为一名**新生**，我想在对话里看到吉小农用小麦苗贴纸回应我，以便这个助手感觉像个有温度的伙伴，而不是一个冷冰冰的检索框。 |
| US-06 | 作为一名**懒得打字的用户**，我想直接点一枚贴纸发出去表达「谢谢/开心/在忙」，以便快速回应而不必组织语言。 |

### 能力四：数据导入与记忆隐私

| # | 用户故事 |
|---|---|
| US-07 | 作为一名**有整理习惯的新生**，我想把自己在别处记的报到笔记粘贴进来，以便这些内容和助手的记忆放在一起、不用来回切换应用。 |
| US-08 | 作为一名**在意隐私的用户**，我想清楚看到助手在我手机上到底存了哪些数据，并能一键导出备份或彻底清除，以便我始终掌控自己的信息。 |

### 3.1 P0 —— 本迭代 MVP（必做）

#### PRD-P0-01 学生档案卡

| 项 | 内容 |
|---|---|
| **标题** | 学生档案卡（昵称 / 专业 / 年级，localStorage 读写） |
| **描述** | 新增 `/profile` 页面，提供一张可编辑的档案表单，字段仅 3 项：**昵称**（文本，≤12 字）、**专业**（文本，≤20 字）、**年级**（单选：2026 级 / 2025 级 / 2024 级 / 其他）。全部字段**必须**为选填，允许留空。数据**必须**写入 localStorage 键 `jxn-profile`，读写**必须**做 try/catch 兜底（隐私模式/配额溢出时静默降级，不得白屏）。保存成功后**必须**通过现有 `Toast` 组件给出反馈。 |
| **数据结构** | `jxn-profile` → `{ version: 1, nickname: string, major: string, grade: string, updatedAt: number }` |
| **验收标准** | ① 填写并保存后刷新页面，三项内容仍在；<br>② 全部留空时保存不报错，且不影响问候语（走默认文案）；<br>③ 手动把 localStorage 中该键改成非法 JSON，页面**必须**正常渲染为空表单而非崩溃；<br>④ 昵称超长时输入被截断或给出提示，不得写入超长值。 |

#### PRD-P0-02 前端问候语个性化

| 项 | 内容 |
|---|---|
| **标题** | 基于档案 + 记忆的问候语个性化 |
| **描述** | 将 `ChatPage.tsx:13` 的常量 `WELCOME_TEXT` 替换为一个纯函数 `buildGreeting(profile, memory)`，在**对话空态**（`ChatPage.tsx:288` 首条 assistant 气泡）渲染。降级链**必须**逐级生效：<br>① 有昵称 → 「{昵称}，你好呀～」；无昵称 → 「同学你好」；<br>② 有专业 → 追加「{专业}的事，我也知道一点。」；<br>③ 有记忆条目 → 追加 1 条关怀语（从记忆库随机取 1 条渲染，如「今天也要好好吃饭呀～」）；<br>④ 三项全空 → **必须**完全回退到现有原文案。<br>**硬约束**：此需求**仅**改变前端展示文案，**禁止**把 profile/memory 拼进 `/api/v1/chat` 的请求体，**禁止**改动 `streamChat` 的调用签名（D5）。 |
| **验收标准** | ① 填「小吉 / 动物医学 / 2026 级」后进入对话，空态气泡显示带昵称与专业的问候；<br>② 清空档案后问候语回到原文案，逐字一致；<br>③ 用抓包/DevTools 检查 `/api/v1/chat` 请求体，**必须**与改动前完全一致（字段无新增）；<br>④ 已有历史消息时（非空态）不显示问候语，行为与现状一致。 |

#### PRD-P0-03 历史记忆（关键偏好）

| 项 | 内容 |
|---|---|
| **标题** | 关键偏好记忆库（显式录入，无自动解析） |
| **描述** | 新增 localStorage 键 `jxn-memory`，存放用户的关键偏好条目。**录入方式仅两种显式入口**（遵循 D4，**禁止**做 NLP 自动抽取）：<br>① **对话内「记住这条」**：用户自己的消息气泡下方新增一枚极轻量 ghost 动作（复用现有 `.btn-ghost` 体系，文案「记住这条」），点击后把该条消息文本存为一条记忆；<br>② **档案页手动添加**：`/profile` 页「关于我」分区支持手动新增/删除条目。<br>条目上限 **50 条**，超出时**必须**拒绝新增并提示；单条文本 ≤100 字，超出截断。 |
| **数据结构** | `jxn-memory` → `{ version: 1, items: [{ id: string, text: string, source: 'chat' \| 'note', createdAt: number }] }` |
| **验收标准** | ① 在对话中点「记住这条」，到 `/profile` 的「关于我」列表中能看到该条；<br>② 删除条目后刷新，条目不再出现；<br>③ 存满 50 条后再点「记住这条」，给出 Toast 提示且不写入；<br>④ 记忆条目会被 PRD-P0-02 的问候语消费（至少 1 条时问候语出现关怀语尾句）。 |

#### PRD-P0-04 模块中心

| 项 | 内容 |
|---|---|
| **标题** | 模块中心页 + 模块开关机制 |
| **描述** | 新增 `/modules` 页面作为**唯一中心入口**，承载三块内容：<br>① 顶部**档案卡摘要**（显示昵称/专业，点击进 `/profile`；未填写时显示「完善档案，让吉小农认识你」引导行）；<br>② 中部**模块列表**，每行 = 图标 + 名称 + 一句话描述 + 开关（Switch）+ 进入箭头。开关状态**必须**持久化到 `jxn-modules`；关闭的模块**必须**在列表中置灰且不可进入；<br>③ 底部**隐私中心入口行**（进 `/privacy`）。<br>模块**必须**以**注册表（registry）**形式声明——新增一个模块只需在注册表追加一项配置（id / 名称 / 描述 / 图标 / 路由 / 默认开关），**不得**要求改动模块中心页本身的渲染逻辑。<br>**入口衔接**：在 `ChatPage` 的 `AppShell` 顶栏 `right` 插槽新增一枚图标按钮（置于 `ThemeToggle` 左侧）跳转 `/modules`。 |
| **数据结构** | `jxn-modules` → `{ version: 1, enabled: { [moduleId: string]: boolean } }`（缺省时取注册表默认值） |
| **验收标准** | ① `/modules` 能列出 2 个演示模块，开关可切换且刷新后保持；<br>② 关闭某模块后其行置灰不可点，直接访问其路由**必须**重定向回 `/modules`；<br>③ 在注册表中新增一条假模块配置，无需改任何渲染代码即可在列表中出现（架构师验证点）；<br>④ 从对话页顶栏能一键进入模块中心，返回后回到原场景对话且历史消息不丢。 |

#### PRD-P0-07 隐私中心

| 项 | 内容 |
|---|---|
| **标题** | 隐私中心（查看 / 导出 / 清除） |
| **描述** | 新增 `/privacy` 页面，**必须**提供三项能力：<br>① **查看**：以清单形式列出本应用在本设备写入的**全部** `jxn-*` 键，逐项显示「人类可读名称 + 条目数/大小 + 一句话用途说明」。至少覆盖：档案(`jxn-profile`)、记忆(`jxn-memory`)、模块开关(`jxn-modules`)、对话记录(`jxn-conv-*`)、主题偏好(`jxn-theme`)；<br>② **导出**：一键导出为 JSON 文件（文件名 `jixiaonong-data-YYYYMMDD.json`），通过 Blob + `<a download>` 触发，**不得**上传到任何服务器；<br>③ **清除**：支持**分项清除**与**全部清除**，两者**必须**有二次确认（弹层/确认态按钮，文案明确不可撤销）。清除后**必须**即时刷新页面上的数据清单。<br>页面顶部**必须**有一段说明：「吉小农的所有个人数据只存在你这台设备的浏览器里，不会上传服务器。」 |
| **验收标准** | ① 清单中的条目数与实际 localStorage 内容一致（新增一条记忆后数字 +1）；<br>② 导出的 JSON 文件可被再次解析，且包含所有 `jxn-*` 键；<br>③ 分项清除只清目标键，其他数据不受影响；<br>④ 「全部清除」后应用回到全新状态（问候语回默认、模块回默认开关），且**不得**报错或白屏；<br>⑤ 二次确认可取消，取消后数据完好。 |

### 3.2 P1 —— 应当做

#### PRD-P1-01 吉祥物贴纸面板

| 项 | 内容 |
|---|---|
| **标题** | 自绘吉小农贴纸面板 |
| **描述** | 扩展 `Mascot.tsx` 的表情枚举（现为 `calm` / `happy` / `think`），新增 **3–5 种姿态**（建议：`cheer` 加油 / `eat` 干饭 / `sleep` 休息 / `question` 疑惑 / `salute` 打招呼），组成贴纸集。在 `InputBar` 左侧新增贴纸按钮，点击展开面板，选中后作为一条**用户消息**插入对话流（消息体为贴纸而非文本）。<br>**⚠️ 设计硬约束（PM 已复签，不可违反）**：吉小农是**抽象几何麦苗，非拟人化**——**禁止**绘制眼睛、嘴、四肢、脸；所有「表情」**必须**通过**姿态差异**（茎的弯曲、叶片开合角度、顶芽有无、附加抽象点）表达。着色**必须**一律 `currentColor`，**禁止** hex 与 `<linearGradient>`。 |
| **验收标准** | ① 新增姿态在浅色/深色模式下均正确继承颜色；<br>② 贴纸消息可被 localStorage 会话持久化并在刷新后正确还原；<br>③ 代码审查：新增 SVG 中无 `#` 色值、无 `linearGradient`、无五官路径；<br>④ 贴纸消息**不得**触发 `/api/v1/chat` 请求。 |

#### PRD-P1-02 后台笔记导入面板

| 项 | 内容 |
|---|---|
| **标题** | 纯文本笔记导入 |
| **描述** | 在 `/profile`（或模块中心的独立入口）提供一个导入面板：一个多行 `textarea` + 「导入」按钮。用户粘贴纯文本后，**按空行或换行切分为条目**追加进 `jxn-memory`（`source: 'note'`）。遵循 D4：**不做**任何结构化解析、实体抽取或格式识别，**用户写什么存什么**。导入前**必须**预览将生成的条目数并二次确认；受 PRD-P0-03 的 50 条上限约束，超限时**必须**只导入前 N 条并明确提示。 |
| **验收标准** | ① 粘贴 5 行文本导入后，记忆列表新增 5 条且原文一字不改；<br>② 导入前显示「将新增 N 条」预览；<br>③ 空白/纯空格输入点击导入时给出提示且不产生空条目；<br>④ 触达 50 条上限时提示明确、已导入部分不回滚。 |

### 3.3 P2 —— 锦上添花

| # | 标题 | 描述 | 验收标准 |
|---|---|---|---|

## 4. UI 设计稿

### 4.0 总体原则（沿用「田垄与纸」，不得另起炉灶）

| 约束 | 要求 |
|---|---|
| 配色 | 只用 CSS 变量，**禁止**裸 hex。主色 `--accent`、麦金 `--grain`、纸底 `--bg`、卡面 `--surface` |
| 用色配额 | 单屏 `--accent` 实色填充 **≤2 处**、`--grain` **≤1 处**、浮起卡（`--elev-raised` 及以上）**≤1 张** |
| 禁令 | `backdrop-filter` = 0；彩色 glow 阴影 = 0；inset 白高光 = 0；渐变 = 0 |
| 间距 | 严格 4 栅格，页面左右边距统一 `--space-gutter`(20px)，分区间距 `--space-section`(28px) |
| 圆角 | 卡片 `--radius-lg`(16px)、大卡 `--radius-xl`(20px)、控件 `--radius-sm`(8px)、CTA `--radius-pill` |
| 布局 | **左对齐优先**；用 `.section` + `.section-label` 分区 + `.divider` 发丝线制造节奏，**不是**每组套一张浮起卡 |
| 图标 | 功能图标走 `Icon.tsx`（lucide，`strokeWidth 1.75`）；品牌图形走 `Mascot` / `BrandMark` / `SceneIcon` |

- ✅ **不改动 `/api/v1/chat` 请求体**：个性化只影响前端渲染（D5）。
- ✅ **不引入登录 / 不引入服务端存储**（D1）。
- ✅ **不做 NLP 自动抽取**：记忆与笔记全部显式录入（D4）。
- ✅ **吉祥物非拟人化约束不可违反**：无五官、无四肢、`currentColor`、无渐变（D3 + `Mascot.tsx` 既有约定）。
- ✅ **会话持久化逻辑零改动**：`ChatPage` 的 250ms 防抖落盘 + 卸载立即落盘不得动。
- ✅ **遵守「田垄与纸」设计系统全部硬约束**：见 `docs/design_refresh_system.md` §2 与 §7 验收清单。
- ✅ **所有新增 localStorage 键必须以 `jxn-` 为前缀**，并统一由 `lib/storage.ts` 出入。
